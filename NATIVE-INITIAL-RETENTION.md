# Retain the first native export before web import

The private native-output publisher now emits `htkk-web-native-output-reference-v2` with both `01GTGT-initial.xml` (the original GUI's first export) and `01GTGT-native.xml` (its original reexport after web import). The existing raw reexport name is preserved for consumers. This format is **not** the reviewed `htkk-windows-evidence-v2` qualification manifest.

Staging happens only after the supplier has stopped. Both original files and copies must match the GUI's exact SHA256 and byte counts; reparse points/extra files/unsafe paths fail closed. Live publication requires staging-v2 with the actual `GITHUB_RUN_ATTEMPT`, source/builder/run identity, synthetic case and immutable input artifact. Historical v1 envelopes remain readable by the legacy interface, but live execution never falls back when the first file or attempt is missing.

The first export has the GUI-generated current signing date. The web input deliberately carries a fixed synthetic signing date; the reexport must preserve that exact date. Initial privacy validation checks the first date against its native creation date; final privacy validation checks the fixed input date. Neither validation rewrites published bytes. The publisher records whether every native leaf and attribute actually matches, without normalizing dates or the four service identities. A false comparison remains false and qualification stays closed. Retaining a pair is not proof of complete roundtrip compatibility or independent XSD verification.

All authenticated input reads and writes happen after both outputs have passed their separate strict synthetic privacy checks. Only private Git blobs receive the XML. Public output remains bounded status/commit/hash metadata, with no raw XML or paths. A future post-workflow collector must independently authenticate the completed run/attempt, retain producer/input/audit records, perform XSD and full scoped comparisons, and obtain actual independent review before issue #6 can close.

Validation: `python -m unittest discover -s scripts -p 'test_*.py'`; new tests cover distinct byte streams, attempt substitution/types, missing files, symlinks/extra files, date/identity comparison, immutable private blobs and rejection before authenticated I/O. Windows evidence must be linked separately; these synthetic tests do not prove native execution.

Current live staging-v3 alignment is described in [NATIVE-SIGNING-ALIGNMENT.md](NATIVE-SIGNING-ALIGNMENT.md). The current-date initial signing rule above describes historical staging-v2, not a permitted live downgrade.
